# Проверка запуска снятия просроченных броней по расписанию

29 октября 2026 года, 1С:Предприятие 8.3.27.1688, учебная версия, macOS. Исполнитель автоматизации — Codex. Отдельная база .build/scheduled-job-check/base восстановлена из DT 1.2.1; диагностические обработчики добавлены только в копию исходников. Рабочая база, исходники configuration и поставочные DT/CF не менялись.

## Исходное расписание

В базе присутствует одно регламентное задание, Использование = Да. Представление расписания: «один день; один раз в день». ПериодПовтораДней = 0, ПериодПовтораВТечениеДня = 0. Минутного повтора нет. Параметры зафиксированы в schedule.txt.

## Проверка

Созданы две проведённые брони: просроченная на 5 л молока и будущая на 3 л. Склад 75 л, резерв 8 л. Клиент 1С оставался открытым, обработчик ожидания опрашивал состояние раз в 10 секунд и не запускал процедуру снятия вручную.

Через 70 секунд обе брони всё ещё проведены; резерв равен 8 л. Так воспроизведено наблюдение пользователя: ожидание минуты само по себе не переводит просроченную бронь в непроведённые.

В этой же тестовой базе изменён существующий экземпляр регламентного задания: ПериодПовтораДней = 1, ПериодПовтораВТечениеДня = 60, Использование = Истина, ИмяПользователя = Администратор. Через 60 секунд после настройки планировщик отменил проведение просроченной брони. Будущая бронь осталась проведённой, склад 75 л, резерв 3 л. Прямого вызова УчетФермы.СнятьПросроченныеБрони в наблюдателе нет.

scheduler-run.txt содержит весь журнал ожидания. server.bsl и observer.bsl сохраняют условия проверки; временный код не включён в поставку. Это автоматическая проверка планировщика с реальным ожиданием, не ручная проверка щелчков.

## Вывод

В поставке нет обещанного минутного расписания. Для сценария показа необходимо настроить существующее задание в самой базе, включить ежедневное повторение каждые 60 секунд и оставить сеанс Предприятия открытым. Изменение шаблона расписания в Конфигураторе не обновляет автоматически настройки уже созданного предопределённого экземпляра. Автоматическая отмена после этой настройки подтверждена.
