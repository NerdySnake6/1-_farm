# Исправление DEF-001 и DEF-002

Дата: 29 октября 2026 года. Версия исправления: 1.2.1. Платформа: 1С:Предприятие 8.3.27.1688, учебная версия, macOS. Исполнитель автоматического прогона: Codex.

## Причина и изменение

Роли разрешали проведение и отмену проведения, но не содержали InteractiveChangeOfPosted — «Интерактивное изменение проведённых». Поэтому первичное проведение через форму работало, а повторная запись проведённого документа завершалась ошибкой «Недостаточно прав для изменения проведенных».

Добавлено только недостающее право: Покупка — Приход; Продажа — Расход и Бронирование; ПолныеПрава — все три документа. Изменены также генераторы ролей, чтобы они сохраняли это право при повторном формировании. Права на чужие операции и администрирование не расширялись.

## Воспроизведение и перепроверка

Отдельная база «before-base» восстановлена из DT 1.2.0 и обновлена исходниками до исправления. Ошибка воспроизведена через метод Записать управляемой формы на повторном проведении. Она возникла у рабочих пользователей, а также у Администратора. Протоколы находятся в «До_исправления»; строки ERROR в этой папке являются результатом воспроизведения дефекта, а не неудачной проверкой исправления.

Отдельная база «after-base» восстановлена заново и обновлена исходниками 1.2.1. Протоколы «После_исправления» подтверждают 55 успешных проверок: Покупка — 9, Продажа — 20, Администратор — 26.

Для каждого разрешённого документа выполнены первичное проведение 2 л, повторное проведение после получения формы по сохранённой ссылке, изменение количества на 3 л, отмена, повторное проведение и итоговая отмена. После каждого действия проверены склад и резерв. Повторное проведение не удваивает движения. Не относящиеся к роли документы не получили право изменения проведённых.

Под Продажей и Администратором дополнительно выполнена связанная цепочка: бронь 20 л → продажа → повторное проведение продажи → отмена продажи → отмена брони. Контрольные состояния склада/резерва: 75/20 → 55/0 → 55/0 → 75/20 → 75/0.

В папке «Регрессия» сохранены 83 успешные проверки: учёт — 21, формы — 10, права Покупки и Продажи — по 9, бронирование — 28, команды формы брони — 6. Это новый прогон, а не повторная публикация исторических результатов.

Новый DT 1.2.1 дополнительно восстановлен в новую базу сохранённым скриптом. Повторены те же 55 проверок, все успешны. Протоколы находятся в «Проверка_DT»; повторный прогон не прибавляется к числу уникальных проверок.

## Статус дефектов и ограничения

DEF-001 и DEF-002: исправлены в исходниках и поставке 1.2.1; автоматическая перепроверка через управляемые формы успешна. Позднее Ефимов С.Р. передал ручное дополнение от 29 октября: MP03 и MS01–MS03 отмечены успешными, дефекты закрыты. Точная версия повторной ручной базы в дополнении не названа; автоматические результаты 1.2.1 подтверждены отдельно. Программная запись формы не объявляется щелчком мышью. Исторические наблюдения Ефимова С.Р. в Word-отчёте сохранены. Карточки DEF-001 и DEF-002 дополнены результатами исправления, приложение Г содержит проверенные значения, приложение Д — новые снимки интерфейса из PR №3. Полный smoke-тест отмечен исполнителем пройденным, однако повторный пошаговый журнал не приложен. Ручное дополнение приведено в приложении Е.

Рабочие базы не изменялись. Проверки и временные тестовые обработчики находились в .build/posted-rights. Чистый DT сформирован из отдельной базы, восстановленной из исходного демонстрационного DT и обновлённой исходниками 1.2.1; в неё не загружались временные тестовые обработчики и не вводились тестовые документы. Контрольные остатки демонстрации: 75 л, 15 кг, 12 кг; активных броней нет. Пользователи сохранены без паролей.

## Повторение

Из корня проекта: `python3 scripts/check_posted_document_rights.py`. Скрипт создаёт новую папку в .build, восстанавливает DT, копирует исходники, добавляет обработчики только в копию и запускает 55 проверок под тремя пользователями. Путь к установленной платформе можно указать через --v8-path. Для исходной версии предусмотрены --source и --dt; старые исходники без исправления ожидаемо дают ошибки прав.

Полная генерация конфигурации остаётся несогласованной с доработками Ivanov-f. Для загрузки используйте актуальную папку configuration или CF 1.2.1; запуск extend_configuration.py пока может убрать новые объекты из состава конфигурации.
