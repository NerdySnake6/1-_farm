# Исходники и проверка

Актуальные исходники и DT/CF имеют версию 1.2.1. Отчёт по тестированию обновлён для 1.2.1; остальные Word-документы и презентации относятся к 1.2.0; в documentation_facts.json номер исходников указан отдельно в source_configuration_version. Исправление DEF-001/DEF-002 и протоколы приведены в разделе тестирования. Повторная автоматическая проверка прав: `python3 scripts/check_posted_document_rights.py`; она создаёт отдельную тестовую базу и не меняет рабочие базы.

Полную генерацию XML через extend_configuration.py пока не запускайте: генератор ещё не учитывает все объекты Ivanov-f. Для установки исправлений используйте актуальные XML или CF 1.2.1.

Рабочая выгрузка находится в configuration. Она получена штатной командой DumpConfigToFiles установленной платформы. Загружать её следует в отдельную учебную базу: в конфигураторе Конфигурация → Загрузить конфигурацию из файлов, затем обновить конфигурацию базы данных.

scripts/build_configuration.py формирует основные метаданные; scripts/extend_configuration.py добавляет формы, роли, отчёты и модули. Полная повторная генерация требует предварительного согласования с доработками Ivanov-f. Используется только стандартная библиотека Python. Исходный шаблон конфигурации сохранён в scripts/templates.

Тестовые модули BSL находятся в scripts/bsl и в соответствующих объектах configuration. Управляемое приложение распознаёт служебный параметр запуска FarmTests=путь_к_проекту. Для записи протоколов должна существовать папка .build внутри проекта. Проверки запускаются под Администратором на свежей копии демонстрационной базы; они ожидают исходные остатки 75, 15 и 12. Не запускайте их на базе с изменёнными учебными операциями: заполнение примера обновляет справочники и цены.

Параметр FarmRole=путь_к_проекту проверяет разрешения выбранного пользователя. Параметр FarmUsers создаёт демонстрационных пользователей; после его выполнения необходимо выбирать пользователя при следующем входе.

Для повседневной работы с системой эти параметры и сборочные скрипты не нужны. Открывайте готовую базу обычным способом.

## Повторная сборка документации

Эти команды выполняются из корня проекта и не запускают 1С. Скрипты перезаписывают только актуальные материалы; архив не включается в сборку.

1. `python3 scripts/build_all_documentation.py --render` формирует пять DOCX, рендерит их, определяет номера страниц содержания и повторяет рендер. Нужны Python 3 с python-docx, pdfplumber, Pillow и LibreOffice, а также render_docx.py из установленного навыка Documents. Путь к renderer задан в скрипте. Без `--render` документы создаются с незаполненными номерами содержания; для итогового комплекта используйте полный режим.
2. `RUNTIME_NODE_MODULES=/абсолютный/путь/node_modules node scripts/presentation/build.mjs` импортирует сохранённый шаблон, обновляет тексты и заметки, проверяет пакет и геометрию слайдов, сохраняет один актуальный PPTX. Нужен Node.js с @oai/artifact-tool. Переменные `PRESENTATIONS_SKILL_DIR` и `RUNTIME_PYTHON` позволяют указать установленные пути навыка Presentations и Python. В шаблоне сохранены реальные снимки проекта; исходный файл находится в assets/templates.
3. Просмотрите все PNG страниц в `.build/documentation/qa` и все PNG слайдов в `.build/documentation/presentation`. PDF и PNG предназначены только для проверки и не передаются как итоговые документы.
4. `python3 scripts/check_documentation.py` проверяет состав, ссылки, номера содержания, протоколы и расчёт контрольного примера.
5. `python3 scripts/package_project.py` собирает `deliverables/Комплект_Молочная_ферма_v1.2.0.zip`, проверяет целостность и SHA-256 каждого включённого файла. Упаковка сначала запускает проверку документации.

Реестр согласованных чисел хранится в scripts/documentation_facts.json. После изменения поведения конфигурации нужно проверить и содержательные тексты, а не только номер в реестре. Скрипт build_documentation.py оставлен как совместимая команда для общей документации.

ZIP содержит Word, PowerPoint, DT/CF версии 1.2.0, исходники configuration, assets и scripts, технические материалы и первичные протоколы. Рабочие каталоги баз, архивы прежних поставок, шаблонные временные файлы и результаты рендера исключаются. После распаковки для запуска нужно восстановить DT в отдельную базу; готовый рабочий каталог базы не упаковывается.

## Сохранность исходных материалов

Архив прежних документов и презентаций находится в Документация/Архив/2026-10-23, архив прежних ZIP — в deliverables/Архив_поставок. Реестр_архива.json содержит исходные пути и контрольные суммы. История версий 1.1, 1.1.1 и 1.2.0 сохраняется как отдельные технические записи. При переработке документации рабочие базы и метаданные конфигурации не изменялись.

Бронирование добавляется модулем scripts/reservation_extension.py при запуске extend_configuration.py. Объектные и серверные модули доработки находятся в scripts/bsl/Бронирование*.bsl. Команда `python3 scripts/platform_step.py reservations .build/отдельная_тестовая_база` запускает 28 проверок учёта брони и 6 проверок обработчиков форм. Используйте только отдельную восстановленную копию: сценарии создают и удаляют тестовые документы. Прогоны прав purchase/sales выполняются отдельно. На рабочей базе эти команды не запускаются.

## Обновление отчёта по тестированию

`scripts/update_testing_report_121.py` вносит поправки в существующий отчёт, сохраняя заполненные ручные результаты. Он проверяет протоколы перед добавлением перепроверки и снимков; повторный запуск не дублирует приложения. Генератор build_testing_documentation.py сохраняет отчёт с этим дополнением и проверяет его протоколы вместо перезаписи ручных результатов историческим шаблоном. После правки содержимого необходимо отрендерить документ и синхронизировать номера страниц содержания.
